title: "A broken file is an invalid document with its identity, and nothing stops the build"
---
Duplicates make every holder invalid; an unreadable front matter keeps its identity; gone and unknown are told apart; the text is normalized before it is hashed; a value a front matter does not hold is told with the kind it was read as, in words of its own, and the usual causes with how to write the value. A file under no book, one whose directory the schema has moved included, is outside the books; a file with no id is anonymous, and one whose id is not text or no identifier is unreadable; a key left out, not text, of another prefix or with a leading zero, an entry the book does not declare, a field of another type than the book declares, a word an enum field does not take, a link to documents that is no list or has a count its cardinality does not admit, and a link to artifacts that is no list, are each a problem, and every problem of a file is listed. An integer is a whole number with a minus sign or none; a bool is true or false only; an enum takes only its own words as written; a text list takes no single text. A well-formed file is a valid document with its key, file, body and fields, every link of its book there and empty when none is written, and a key whose prefix could be read as hexadecimal is still a key. A link resolves to the valid document with the key; a link in the wrong grammar is malformed, one to no key is missing, one to a key two documents hold is ambiguous and names both files, and one to an invalid document cannot be stood on; looking up a key tells valid, invalid, ambiguous or missing, and the same id and key in two files is one invalid identity, not an ambiguity. The presence of a valid document has its key, file and hash; the failure of an invalid identity carries every problem of its files; the identities of a shelf are those some file carries, and an identity may be in the files that carry it or, while none does, in any file whose identity cannot be read.
