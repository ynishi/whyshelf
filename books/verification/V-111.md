title: "The text of a rust-test name holds the items beside the test in its test part and the test-only modules and items of its crate that it reaches, and never the code under test"
---
Infra (the tests of rust_test): an edit of a helper, a constant or a use of the test part, or of a helper in an inline module inside it, changes the text of a test of the part, and of a test in that inner module (an_edit_of_an_item_beside_a_test_in_its_part_changes_its_text); an edit of another test, at the top of the part or in a module inside it, of the code outside the module that holds only under test, of a doc or of the spacing of an item beside keeps it, and no other test is in it (an_edit_of_another_test_or_of_the_code_under_test_keeps_the_text); an inline module of the part renamed, made public, or added holding tests only changes the text of no test, the one in it among them, a helper edited in it still changes every one, its attributes stand before each of its items, so an item moved out of it or an attribute taken off it changes the text, and each line inside it is marked with its depth, one > a module, so two helpers of one name swapped across its boundary change the text (a_module_in_the_part_is_read_through_so_its_name_counts_for_nothing); a module declared out of line and an include are their declaring tokens only (a_module_declared_out_of_line_is_its_declaration_only); in a file of tests with no module that holds only under test a helper at its top is beside the test, a cfg of test (a comma after it or not), of all holding test and of any each holding test starts the part, one that may hold otherwise or in a cfg_attr does not, and the outermost such module on the way is the part (the_test_part_is_the_outermost_module_that_holds_only_under_test_else_the_file); a name asked alone, with others and in another order reads the same, and the tests of one part share its text (a_name_asked_with_others_in_any_order_reads_the_same); twin parts are each beside in the order of the file (twin_modules_are_each_searched_and_twin_functions_are_one_test). The texts the other tests of the module expect hold the items beside, and the conformance test (V-103) reads a tree whose tests have helpers beside them. What a test reaches outside its part (rust_test/tree.rs): a test that names a helper module holds it and one that does not holds nothing, and a test that holds nothing keeps the text it had with no crate read; a held module names what it holds in turn, once, and a test holds no module it is in; the file of a module is found by the rules of the reference (x.rs, x/mod.rs, a path attribute, an inline module a directory step), and a module is compiled only under test by a cfg that holds only under test; an alias, a re-export and a glob name a helper, and the code under test is never held; a macro exported, a macro_use and an impl of a type declared elsewhere are held by every test of the crate, and an item of the test residue by the tests that name it (a member name after . or ::, not a local), by every test when no name reaches it, or through a use by the tests of its subtree; two modules of one file are two parts, a module of tests only is none; a file in two targets holds what it names of each; an include with a literal path is held by its hash and another cannot be told. A path holds a module by the module it names and not one of the same name (a local or a parameter named like a module holds nothing, super and crate, self and a child, a use tree and its aliases, a path of another crate or above the root, the inline module a path is written in, a macro that resolves where it is called). What cannot be read cannot be told, for the tests that reach it only (a module that cannot be read, a file in no crate while something was not read, a file under a module that cannot be read). A test lives in its own file and the files it holds, and a space reads the trees once and answers as fresh spaces do.
