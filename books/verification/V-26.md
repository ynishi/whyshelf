title: "Spaces are declared, names are answered four ways, and old pins read as files"
---
A link to artifacts with no space or an unknown one is refused. A text that is no name, or that the adapter answers is not a name, makes the document invalid. An approval on a name that cannot be told is refused and writes nothing; a pinned name that later cannot be told is a notice and the approval stays fresh. presence ignores content and tells present from absent. A stored pin without a space reads as file and its record is unchanged, and every record of the repository's own ledger reads with no problem and writes back as stored, with the same hash. A new pin writes its space and its name and no path; a pin that writes both a path and a space with a name, or neither, is refused, and so is one whose space is no space. One name in two spaces is two artifacts, and a link moved to another space names each artifact in its own space. The names the build asks for are those the files under a book write, each once in its link's space, a text such as /abs included, since whether it is a name is the adapter's answer; a file under no book is asked nothing. A space is a lower-case word of at most forty characters that begins with a letter and holds only letters, digits and hyphens; a name is any text that is not empty, holds no control character and is not too long, its white space at the ends kept; an address or a revision is not empty and holds no space; an artifact's hash is never the hash of a document of the same bytes; a reading that cannot tell or is not a name says why, an address is kept only on a thing found, and a name with no answer or a comparison not asked cannot be told (artifact.rs). A path of the project is relative, its segments neither empty nor . nor .., with no backslash or control character, and the empty text and an absolute path are each refused with an error of its own, a/../b, a//b, ./a and a/ as a bad segment, and a backslash or a control character as a bad character (location.rs).
