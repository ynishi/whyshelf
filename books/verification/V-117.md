Who writes a key (build/keys_tests.rs): a file whose key reads and whose identity does not still writes the key, so the next key passes over it, a key given is refused and it is among the files writing it (a_file_with_no_identity_still_writes_its_key); a link to a key only such a file writes is NoIdentity, and so is the lookup of the key (a_link_to_a_key_only_a_file_with_no_identity_writes_says_so); a collision names every file and the identity of each that reads, each file is invalid with a problem that names the other, and a link to the key is ambiguous between the files (a_collision_names_every_file_and_the_identity_of_each_that_could_be_read); a file that could not be read may write the keys of its own book only (a_file_that_could_not_be_read_may_write_the_keys_of_its_own_book_only); the links that write a key are read from invalid files too, a list with a blank item among them (the_links_that_write_a_key_are_read_from_invalid_files_too, a_list_in_a_link_is_read_for_its_keys_even_when_the_file_is_invalid), and a file of a linking book that could not be read, or a link that is no list, is named as not read (a_place_a_link_may_write_a_key_in_and_could_not_be_read_is_named); what an identity is called now keeps the four states (what_an_identity_is_called_now_keeps_the_four_states). A reference to a key only a file with no identity writes is NoIdentity, in its book or alone, and a document that is found is not hidden by it (lookup/tests.rs, a_key_only_a_file_with_no_identity_writes_names_the_file_not_a_document). On the ledger (ledger/readers_tests.rs): an approval again over an upstream renumbered since it was pinned repeats (an_upstream_renumbered_since_it_was_pinned_is_the_same_upstream_to_a_repeat), and a pin is named by the key its upstream has now, with the key pinned beside it, or as invalid or gone (a_pin_is_named_by_what_its_upstream_comes_to_now). The plan (rekey/rekey_tests.rs): with no other writer every link follows, and a word against that is a contradiction; the pins of the approval that stands say which document a link meant, and the pin of another link says nothing of it; a document with no approval is undecided until a word; a word is laid beside the pins and not dropped; pins on both sides are a contradiction until --both; every document not decided is listed; a file that could not be read and a link that is no list stop the plan and are named; the target is one file with a key that reads; a key given must be free; a word names a document that writes the key in a link; the documents whose body names the old key, as a whole name, are listed and left as they are; the entries of a plan change only the key and the items that follow or keep both; the files a plan writes build the shelf it said, and files that do not, or that changed since the plan, are refused with every difference (confirm). The use case over the fake (app/shelf/rekey_tests.rs): the document moves to the file of its new key and the links that mean it follow; --both keeps the old key and adds the new; a dry run is the same plan and writes nothing; a document not decided is refused with every such document and nothing written, and one named twice is refused; something at the new file refuses it before anything is written; a stop before the removal puts every file back and says why, and one that cannot be undone names what is not back; a file changed before it was written over stops the run with nothing left; a removal that cannot be put on disk leaves what was written and names it. No module but the run of writes calls a write port, restore, remove_read and persist_gone among them (run_writes_tests.rs, no_module_but_run_writes_calls_a_create_port). On the files (infra docs.rs): the bytes create writes are the text render gives (the_bytes_create_writes_are_the_text_render_gives), and a file is put back over what was written, and removed only while it is what was read (a_file_is_put_back_over_what_was_written_and_removed_only_as_it_was_read); the removal of a file is put on disk by its directory (create.rs, the_removal_of_files_is_put_on_disk_by_their_directories).
