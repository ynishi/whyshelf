title: "Every write of a run passes one entry, which puts what the run wrote on disk once whichever way the run ends, and files are put on disk per platform with one flush per device"
---
new and new --from put every file they wrote on disk once after the last write, a replanned file included and the taken one not; a run that writes nothing puts nothing on disk; a run that stops part way puts what it wrote on disk and then answers PartWay, and when that fails too says both and is failed; files all written and not put on disk are NotDurable, kept and named. init puts the declaration, its files and its documents on disk once, and the same for its failures; init refused before it writes puts nothing on disk. The futures of the use cases that write are Send, and no module but the one of the run calls a port that creates a file. Files made in nested directories are put on disk whole, a path that is not there cannot be, the files the project's three writers wrote are put on disk through the project, and a device that cannot flush fully is left at fsync while any other failure is told, with one flush per device.
