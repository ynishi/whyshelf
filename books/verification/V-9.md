title: "The latest decision stands, conflicts are set aside, and records read back as written"
---
Two records with one identity are set aside; a revocation of an id no record has, of a revocation, or of an id whose records conflict withdraws nothing of that target and is a problem of the ledger, while its other targets still count; a record reads back strictly into the same value and hash. A document nothing was decided about is pending; an approval keeps the hash it saw and a later denial stands over it; a revocation withdraws the decision it names, leaving the document pending with no problem; a retirement writes what it saw as a state and a hash and reads it back. A sound pin reads back, while a pinned key whose tail no document could have (0, 007 or a number too long), whose kind is not what its text reads as, or of a kind this reader does not know, a frame that pins one link to one document or one path of one link twice, the pin of an absent artifact that carries an address, and a revision that holds a space are refused. An approval with no artifact and no address, in a project that declares no rule of who may decide, writes only the keys of the first version: actor, at, expires, frame, id, kind, reason, seen, subject, v and verb. A hash is written as sha256: and 64 lower-case hex digits and reads back the same, and a text without the prefix, of another length or with capitals is refused; each kind of hash, of a document, a judgement and an artifact, has its own tag, so equal bytes of two kinds hash apart, and a fixed document gives a fixed digest. The directory of the ledger and each record file are read as the system reads them, through a link out of the root too; a directory behind a broken link is an empty ledger, and a record file that is a broken link or a directory stops the read (readers_tests.rs).
