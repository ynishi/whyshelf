On the binary and a small project (ran_by.rs, which sets the variables it means to and removes the other, so the caller's environment changes no answer): --ran-by is kept beside the actor in the record the answer shows and the file holds (a_ran_by_given_on_the_command_line_is_kept_beside_the_actor); the variable names it when the line does not (the_variable_names_who_ran_the_command), and the line wins (the_command_line_wins_over_the_variable_for_who_ran_the_command); a ran_by equal to the actor, from either source, writes no key (a_ran_by_that_is_the_actor_is_one_name_whoever_gave_either); Git's user.name and the files of the project name no one (gits_user_name_and_the_projects_files_are_not_who_ran_the_command); a blank variable is none and a blank --ran-by is a wrong request that writes nothing (a_blank_variable_names_no_one_and_a_blank_flag_is_a_wrong_request); every verb of judge takes --ran-by (every_judge_verb_takes_a_ran_by) and a revocation keeps it (a_revocation_keeps_who_ran_the_command_too); the decision of a row, get --approved and status show ran_by beside the actor, null when the actor ran the command (the_answers_show_who_ran_the_command_beside_the_actor_and_null_when_it_is_the_actor); the exemptions check lists show it (the_exemptions_check_lists_show_who_ran_the_command_beside_the_actor). The repository's own ledger still reads with no unreadable record and no problem (repository_ledger.rs).
