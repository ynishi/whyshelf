title: "Editing a file an approval stands on makes it stale, and diff shows the change"
---
Approve a document that links test files; edit one; stale names it with artifact_changed; diff shows the approved and the current text; the text of diff is a unified diff, none for the same text, a changed line removed and added with three lines of context around it, changes far apart two hunks and near ones one, a text from nothing all added and one to nothing all removed, and an insertion with the lines around it; a file the adapter gave no answer for is unknown and not absent, in diff changed with no hash now and no file, and as the target of a trace with no hash; a path with no file is absent, and its arrival makes the approval stale. A file unchanged keeps the approval fresh, a file there then and gone now breaks it, and a path with no file then and now changes nothing; a path written or dropped since is a change of the links to artifacts, stale, naming the paths added and removed, and the cause gives a space when every name added and removed is of that space and none when they are of two, its detail naming each name in its space; an informs link to a file changes no freshness when the file is edited; a document that stands on one whose file changed is stale through it; and the hash of a document does not cover the names its links to artifacts write. The approved content of an item is read by the address it was recorded with, and an item with no address, or with one that could not be read, says which. In the answer, an approved content read as UTF-8 gives its text and its count of bytes, one that is not UTF-8 its count of bytes and no text, and an item with no address no count. Outside a repository the freshness is the same and no address is recorded; an address read back from a record is checked before Git is asked for it. In a repository the address of a file read, and of a document's file, is the blob Git would store for its bytes in the work tree, not the one the index holds, and a document's file that is not there has none (readers_tests.rs).
