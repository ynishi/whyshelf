title: "On the binary and the docs cargo doc writes, an approval of rustdoc-promise stays fresh through an edit of a body and goes stale through an edit of docs, of a signature, of a variant's field, or docs taken away"
---
The test writes a crate with no dependency into a temporary directory and runs cargo doc offline into a build directory of its own, without the flags of the machine, with the toolchain file of this repository beside it, and fails unless the rustdoc that wrote the pages is of the channel that file pins. A note links to a crate, a module, a function, a struct, a field, a method, a variant with a field and a method of a trait with the preset rustdoc-promise: check finds none absent or unknown and the approval is made, which no unreadable name would allow. After an edit of a body, a method added and an impl added, the note is fresh. An edit of the docs of a method, of its signature, of the docs of the field of a variant, and docs taken away, each make it stale with artifact_changed and the name of the item, and each is approved again. Once the page of an item is gone the approval is broken. A note approved under the preset rustdoc stays fresh through an edit of docs, its diff says the item is there and unchanged, and once its link names rustdoc-promise it is stale with artifact_comparison_changed.
