On the binary and one small project of files (reach.rs): reach of a requirement answers it, named, the decision that serves it and the verification that checks that decision, not the requirement apart nor its decision; the file the decision's code link names, placed in that file only, and the test the verification's tests link names, placed in the file before ::, each with the document that stands on it; the files of the three documents and of the two artifacts; nothing unplaced, nothing gone, no count of what could not be followed, and no warning. A decision whose file has no title, which serves the requirement, is not reached and is counted as one document whose links cannot be read, with the warning of it on stderr, while reach of two requirements answers the documents of both; a reference that names nothing, and no reference at all, are request errors (exit 2). reach is one of the reading commands every answer and no write are checked of (common/mod.rs).
