title: "Runs of new with no key at the same time chose the same next number, and all but one failed as if a key asked for were taken"
---
new with no key chose the next number from one reading of the shelf, then wrote the file create-only. Runs started together in one working tree read the same shelf and chose the same key; every run but one found the file there and failed with the error of a key asked for and taken (five of eight runs in a test). The key did not keep whether it was chosen or asked for, so the use case could not tell a key to choose again from a request to refuse. The same gap stopped new for good when a file whose front matter cannot be read held the next number: the shelf saw no key there, so new chose it every time.
