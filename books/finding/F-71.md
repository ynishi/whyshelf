title: "rust-test lists no names, so a link that names tests by function cannot declare a cover, and a test no verification names would be found by nothing"
---
This repository's verifications name the files of their tests whole, under tests, in the space file, so the edit of one test makes stale every verification that names its file, those that rest on other tests of it among them. Naming the tests by function (the space rust-test) would make stale only the verifications that rest on the test edited. But once names are written by hand or by a script, a test that no verification names is left in silence: today the pin of the whole file covers it, and after the move nothing would. A check finds such a test only through a cover on the link that names tests, and a cover is declared only over a space whose adapter lists the names a selection takes (DEC-93); the adapter of rust-test listed none, so a link with the preset test could declare no cover.

Issue #120 resolves it: rust-test lists the tests of the files a selection takes (DEC-111). As the rule of DEC-111 reads what may make a test, the listing of many of this repository's files is not whole: when it was made, counted by the lines of the tracked .rs files of the crates, 89 of them, 71 for a derive of a crate (thiserror::Error, serde, clap), 11 more for a test attribute of a crate (tokio::test), 4 more for another attribute macro (tokio::main on fn main, arch_lint on items and beside a test) and 3 more for a derive of the standard library's written in a module that holds a glob use (use super::*; in a file of tests, or in its mod tests). Naming the tests of those files by function needs a line of the exclude of the cover for each, or a change of that rule.
