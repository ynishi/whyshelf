title: "new wrote one document per run and read the whole shelf each time, so adding many documents cost the number of documents times the size of the shelf"
---
A caller that adds many documents at once (an import, a tool that files what a run found) ran new once per document, and each run read every document of the project first: 25 runs took 0.23 s on an empty book and 0.93 s on a book of 1000. There was no way in the model to plan several new documents against each other and the shelf at once: new planned one, and init planned several by building the shelf again for each document and once more for its heads.
