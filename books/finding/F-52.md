title: "A record of the ledger was written and made durable by its own call, outside the run of the use case, so a failure part way left some records and a run cost a flush a record"
---
The six use cases that write records to the ledger (judge, approve, same meaning, moved, exempt, withdraw) appended each record on its own: the file was synced one at a time, outside the run of writes that new and init take, and a write that failed part way left its file behind. A declaration of many names at once (judge moved --prefix) would have been the first to write dozens of records in a run: one that failed part way left some of them, and the cost grew by a flush for each. The cause is the one of the flush of each new file: how durable a write is was decided file by file, as a side effect of writing one, and not by the run it belongs to.
