title: "Each new file was put on disk on its own with a full flush of the drive, so a run of new cost a flush per row"
---
new --from read the shelf once for a whole run, but each file it wrote was made durable before the next was written. The one way the adapters create a file synced it on its own, and on macOS the standard library's sync of a file asks the drive to flush its whole cache, which takes several milliseconds: in a project with no document, 100 rows took 0.55 s, about 4.5 ms a row whatever the size of the shelf. How durable a run is belongs to the run, but it was decided file by file, as a side effect of writing one. init wrote its files the same way.
