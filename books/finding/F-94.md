The space rust-item answers from the HTML cargo doc wrote in the build directory, and nothing held those docs against the sources they were built from (DEC-54 read them as they are). On this repository, with the docs of a checkout built before a change landed, stale on the tree after it told a decision broken, four items it names as having nothing behind them, and offered moves and judge moved for each, while the items were in the sources; building the docs again told nothing stale. The other way round follows from the same reading: an item taken out of the sources is still in docs built before, so an approval that pins it reads as holding until the docs are built again. The recipe of the gate builds the docs before it checks, so the gate did not meet it; a person or an agent running stale, check or status between edits met it whenever the docs were older than the tree, and what was told then was wrong and said nothing of why.

Issue #225 resolved it (DEC-116).
