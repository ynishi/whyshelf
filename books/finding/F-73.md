The batch added crates/whyshelf-cli/tests/**/*.rs to the include of the cover of cases (strength error, parts taken whole through tests, no exclude) and moved the verifications that named a file of that region whole under tests. Measured on the branch of the batch: rust-test listed 251 tests of the region in 52 files it lists whole, and one part, the file of this repository's guard of its verifications (verification_spread.rs), read with 17 tests found, a part only for #[tokio::test], a macro that may write more than one test; the one verification that named it whole keeps it so and it is reached. The shared helper of the end-to-end tests (common/mod.rs) holds no test and stays named whole by 50 of the 51 verifications that named it; the one whose file declares no use of it names it no more. No part of the region was unread and none needs an exemption. Before the batch every file of the region that holds a test was named whole by some verification, so no test of the region was named by none. 55 verifications named files of the region whole and all 55 changed; four of them now name nothing under tests. Of the 52 files, 40 were named by one verification and their 152 tests went to it; 12 were named by two and their 99 tests were split by reading each verification's text and each test's assertions. One of the 12 went whole to one verification, whose text claims its tests, while the other keeps none of it, since its text's claim is shown by a test of another file; 11 are split between two. The 251 tests are 255 names under cases: 4 tests evidence a sentence of both verifications that name their file and are named by both. 10 tests are hesitated over: each went to the verification whose text comes nearest, or gained a sentence, and none fits the text of no verification. Thirteen verifications changed their text: eleven sentences were added, each saying what a test asserts that the text did not (among them a revoke with no actor failing on the name first, the command init gives approving four documents and no other, a file where a book directory goes being in the way, an exemption from one of two covering links leaving the other a gap, a git that cannot be run being a failed run, the health of status being of the whole project, and status --with), and three were set right where a test asserts otherwise: a text said a file a macro may make a test in leaves the cover until an exclude takes it out, where the test names it whole under tests or exempts it; a text spoke of a field the test does not use; a text left out that a file of new --from with no line is the error of a request. A blind review then narrowed four sentences, added or old, to what their tests assert, took off one name that evidenced no sentence of its verification, and set the title of the verification over the parts of rust-test right. Three sentences are still shown by no test their verification names, as before the batch: one says check stays clean after fmt leaves out an empty field, and two, of two verifications, say their command is one of the reading commands whose answers and writes are checked, which tests no file under them runs. After the batch check is clean, with no gap and the two exemptions of the trial batch, fmt --check is clean, stale lists exactly the 55 verifications changed, each with links_changed on tests and cases and the thirteen whose text changed also self_changed, and the test of this repository's verifications passes. The guard's tests took 11.44 s on two threads, its rule over this repository not timed alone; its candidates took 7.42 s; the asks of a listing it made were not counted. The full fmt check, clippy, docs and tests took 4 min 53.79 s from a cold build. The time the split by hand took was not measured.
