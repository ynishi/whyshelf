Each batch added its region to the include of the cover of cases and wrote no exclude; every part the region answered was named whole under tests or exempted with a reason (F-72 to F-77, F-80). Each finding states no part unread, so a part that could not be read never had to be judged here. No decision, no code of the domain and no code of the adapters of artifacts, rust-test among them, changed during the batches: git log d58db61..2f0e1dc over books/decision, crates/whyshelf-core/src/domain and crates/whyshelf-infra/src/shelf/artifact lists no commit. What the rule costs is in the tests pinned whole (525, F-81) and the records of exemption (48, F-80). DEC-112 names five conditions on which it is to be revisited. When the links of this repository's verifications are to be named alike once the move is done: the move is done (def460d), so this may be asked now; no batch and no finding has asked it, and this finding does not answer it. When a test file is to be reached through a link: no batch recorded such a need. When an exclusion needs an actor and a time: no exclude was written, and each exemption is a record with an actor and a time. When a cover must choose tests by their module: no batch recorded such a need. When the helpers a test uses are named by its text rather than by hand: that is #205, not yet done. This finding proposes, and does not take, two ways that would let more files be listed whole: moving the tests of a file with a derive of a crate into a sibling file of tests, which leaves the source file a part with no test, to be exempted or named; and rewriting #[tokio::test] (F-87). Trusting a list of macros to make no test stays rejected (DEC-112).
