title: "A file left with both sides of a merge conflict showed the identity of the side it opens with, so the other side's documents were told as gone"
---
Two branches that run new for the same next number add the same file, and Git stops the merge on it. With both sides left in the file, the line that opens the front matter is common to both sides, so Git leaves it outside the conflict markers; the first closing line is the local side's. The reader of a file that could not be read looked for the id up to the first closing line, so it found the local side's identity alone, though it was meant to give none when the lines give two. status then told the documents of the other side as gone, although the file still held them, and the local side's as invalid, as if the file were theirs. check said that the front matter is not valid YAML, and not that the file holds conflict markers. A file whose first line is the marker itself was told as having no front matter, which a book that skips such files passes over without a word.

Issue #166 resolved it for the file and for what check says (DEC-113). The shelf had no value for one of the identities the sides show; issue #217 gave it one (DEC-115).
