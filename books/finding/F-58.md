title: "No practice was written for adding documents to one shelf from several branches at once"
---
Several people or agents add documents to one shelf on different branches, and nothing said how. A trial with three clones of a sample project and a stand-in for the forge, each person adding a requirement, a decision that serves it and a verification that checks it at once, showed: two branches that run new for the same next number write the same file, and Git stops the merge on every file of the group; two files of one key make check report both as invalid, the main branch's documents included, so their approvals are broken until one is renumbered; a pull request checked against an older main branch and merged without running again put the same keys in main; a link to a document of another branch pointed, once that document was renumbered, at the document that holds the key on main, with no warning while the linking document was pending; two approvals of one document made on two branches both stay, and the later stands. A renumbered document kept its identity, and its approvals held, in every case. Renumbering was done by hand.
