title: "An edit of the code under test no longer makes stale the verifications over the tests inline in its file once those are named by function; how much this changed was not measured"
---
The text a name of rust-test comes to is the test's own text and the items beside it in its test part, the outermost module on the way to the test under a cfg of test (DEC-90). A test in a file of its own, an end-to-end test or a file of *_tests.rs, was never made stale by an edit of the code it tests, whether its file was named whole or its tests by function. For a test inline in the file of the code it tests, naming the file whole made every verification that named it stale on every edit of that code, the reason DEC-90 gives for rejecting it; named by function, such a test is made stale only by an edit of its own text or of its test part. How many of the 1585 tests named by function (F-78) are inline in the file of their code was not counted, and the approvals made again since the last batch have not been read by what made them stale, so the change was not measured. It does not hold for the 525 tests in parts named whole (F-81). A helper module a test's file declares out of line or reaches by a path, and a file a test reads whole through include_str! and the like, are not in the text of the test (DEC-90). DEC-112 asks to name whole only the shared helpers of the end-to-end tests that DEC-56 decides; another helper is named only where a verification named it already (common/source.rs of the integration tests of the core, named by one verification, F-76), so an edit of any other helper leaves fresh every verification that does not name it, as before #120. Letting the text of a test hold the helper modules it uses is #205.
