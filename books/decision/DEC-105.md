Where the built docs of the project are is the space rust-item's to say, for each side of a change, from the tree of that side: CARGO_TARGET_DIR as the caller read it; else build.target-dir of the cargo settings at the side's root (.cargo/config before .cargo/config.toml), read as the space file reads a file, through no link out of the root and within MAX_SETTINGS_BYTES; else target beside a Cargo.toml the top of the side's tree lists; each with its directory doc, and a relative directory taken from the side's root. When none can be told, or the settings cannot be read, every name of the space cannot be told, as before.

Docs under the side's directory, reached through no link out of it, are in the project: each place of them is read as the name of the project's tree under the directory of the docs, through no link out of the root, so a page or the directory of a module is read only inside the root, which holds the build directory, and a re-export is followed only when the name its link comes to, links resolved, is under the name the docs come to. Docs elsewhere (outside the root, or reached through a link out of it) are read on the file system where they are, by their canonical paths, a page or the directory of a module only under the root of the project or the build directory and a re-export only under the docs, in a run of one side; a run of two sides tells each name as one that cannot be told, since the place outside the project is of neither side. So each side reads its own docs by one rule: two sides whose settings put the docs in different places each read their own place, and an absolute CARGO_TARGET_DIR under the root of the side after and not under the directory of the side before is outside the project at the side before. A place in the docs is named by its parts below the directory of the docs, and the lookup of a path and the catalog of the names read the docs through the port of the built docs alone.
