Place::of reads, in this order: the document is named; the walk down from the named on the shelf before the change reached it (reach::walk, the one walk reach makes); it is gone before the change (Shelf::state_of), so it was not on that shelf; the walk before could not read everything (its Unwalked, carried as it is); otherwise it is outside. The links the change writes are not walked: the reach is the shelf's before the change, so a document the change adds or puts back is inside only when it is named, and a document outside that the change gives a depends link to the named stays outside. A reference is resolved at the end before; only when it names nothing there is it resolved at the end after, and that end's answer, a document or an error, is the answer. A document the change adds can so be named, and a key the change gives another document names the document before the change; a key only the ledger knows before the change names the identity it had then, so a document that took the key since is named by its identifier, and is otherwise unproven or outside, never passed. A reference that names no document is a request error, whatever --exit-code asks.
