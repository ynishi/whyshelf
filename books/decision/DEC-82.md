---
fmt --drop NAME, repeated for each name, asks for the entry of that name to be left out of the form of a file whose book declares nothing under it (no field, no link, no link to artifacts), whatever kind of entry it was and whatever it holds. The command line only reads each name as a text that says something (an empty one is an argument error, exit 2) and gives them as a DropAsk. The use case calls DropNames::new against the declaration once, after reading it, before any file is read or written: id and key are refused (DropProblem::Reserved), and so is a name every book declares (DropProblem::DeclaredEverywhere, by the one test of whether a book declares a name, the one the build reads each entry by), every problem together and as ShelfError::Drop, exit 2. Shelf::form_entries takes the DropNames, which new gives none of, leaves out an entry whose name is listed and that its book does not declare, and gives the names it left out for that (FormEntries::dropped); an entry that says nothing is left out for its own rule and is not told as dropped. The plan of each file carries those names, and FmtReport::dropped says, for each file written or, for fmt --check, each file that would be, the names it loses: fmt --check --drop is the dry run once the declaration is edited; before that, status --with finds the documents. The safeguards of fmt are as they were: a comment, a read-only file, a hard link, a text that would not read back as the entries of the form, and a change between the reading and the write leave the file alone, with its entry, which check still tells. The entry a rewrite takes out is the unknown entry of a name asked to drop, and no hash changes: a hash covers what the declaration reads, and it changed when the declaration stopped reading the field. status --with FIELD, repeatable, admits a valid document of a book that declares the field and that holds a value for it, whichever; it is one more condition beside --where and --without, is answered for a field every declaring book requires, and with --without of the same field is the request error of a field asked with a value and with no value. A link is no field to it.
