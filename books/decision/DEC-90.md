The text a name of the space rust-test comes to is the test's own text (DEC-64), twins joined in the order of the file, then the text of every other item of the test part of its file, in the order of the file. The test part is the outermost inline module on the way to the test that carries a cfg holding only under test, as an outer or an inner attribute (test, an all of which one holds only under test, or an any of which each does), or the file when none on the way does; twins of a module on the way may be two parts, and each is taken once, in the order of the file. Every item of the test part is taken, the items of the inline modules in it included, except every function rust-test reads as a test, wherever it stands. A module in the part is read through, not taken whole: its name, its visibility and its braces are in no line; each line of an item inside it starts with a mark without a name of how many modules of the part it is in, as many > (no item starts with >, so a mark is never taken for an item, and a line of the part's own level has none), then the attributes of those modules, outer then inner, outermost first, so that they stay tied to the items they apply to; a module with no item but tests is no line, and an item moved into or out of a module, two items of one name swapped across its boundary among them, changes the text. So it keeps REQ-33 and DEC-80: a module renamed inside a test part, made public, or of tests only added to it, changes no text beside, and a move by prefix (judge moved --prefix) follows the test while the other tests of the part stay fresh. Known limitation: where two sibling modules at one depth, with the same attributes, meet, the boundary can shift over their items in their order and change no line, so which module an item is in, and what a test calls by a path or a glob use, can change while an approval of the test stays fresh; this is accepted only there, for items at one depth, in one order, across sibling modules. So an edit of a helper, a use, a constant, a type, an impl or an item macro call there makes every test of the part read as changed; an edit of another test, or of the code outside the test part (the code under test), changes nothing. A function made a test by an attribute rust-test does not read as one (rstest, test_case) and a test written inside an item macro call (proptest) are items beside, so an edit of one makes the other tests of the part stale: the error is toward stale. A module declared out of line, a file an include reads and a fixture are not followed: only the tokens that declare them are in the part, and each is named by its own file (DEC-56). A helper under a cfg of test outside the test part is not compared either, a limit the page of the adapter writes. Each item is printed as a test is, doc attributes left out, and the test and the items beside it are joined in one fixed form that does not mistake one for the other: each item on a line of its own after the test's text, two parts apart by an empty line, and none of them a test. Nothing in a body is parsed or resolved: the items are taken as tokens, and no call is followed. The bounds of bytes and of depth, and the answers of cannot tell, stay as they are. The names, the preset test and the asks stay as they are; an approval of a test made before reads as stale once, unless nothing is beside the test, whose text is then its own as before. Of DEC-64, this replaces the sentence that the text is the function alone, so that what it calls is not compared, and its saying that present gives the function's own tokens; it keeps DEC-64's names, its scan of items that runs no program, its bounds, its answers and its preset test. Of DEC-56, this adds to its body that a helper used by one feature, kept in its file, is held by the text of each test of the file a verification names by function, and rewrites its first rejected reason, that no space named a test function, into why one file for every feature would still make every verification stale; it keeps the rest of DEC-56: a file of end-to-end tests per feature, the shared module common/mod.rs named whole by every verification over those files, the guard on how many verifications name one file, and the names of the temporary directories.
