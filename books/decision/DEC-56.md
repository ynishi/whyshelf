The end-to-end tests of whyshelf-cli are one file per feature under crates/whyshelf-cli/tests, and each verification names the files of its own feature. The helpers the files of one kind of project share are one module, common/mod.rs. The shared helpers are the .rs files of each directory crates/whyshelf-cli/tests/<dir>/ that holds a mod.rs: none holds a test nor anything that may make one, and no verification names one of them, whole under tests or under the link with the preset test: the text of each test that reaches one holds it (DEC-90), as a test means what its helpers do, so an edit of a helper makes stale the tests that use it and no others, and a test that starts to use a helper holds it with no name written; a helper used by one feature stays in its file, which the verification names whole, or, where it names the tests of the file by function, which the text of each of them holds (DEC-90); and a file whose project is made another way keeps its own. A test reading this repository's verifications fails when a verification names a shared helper, with the way to drop the name, and when a file there other than a shared helper is named, whole or by its tests, by more than two, so an edit of one feature's tests leaves the approvals of the others fresh. Every temporary directory these tests make by hand holds the name of its test or feature and a counter, so tests run in parallel never share one.
