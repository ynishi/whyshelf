title: "The way a change is read is chosen once, at the composition root, by the form of the flags, and every reader of the run holds the one tree it opens"
---
The command line turns the form of its flags into a ChangeAsk: --since with --until or --index is Git (the default after is HEAD), --before with --after is two directories (the default after is the project root); both forms at once, or neither, is a request error (exit 2). Project::for_change opens the one tree the ask names (GitStates, or FileStates::between) as a ProjectTree, a closed sum whose arms are private and made by its two constructors only, and builds every reader, every space and the built docs of rust-item on clones of it, by the one assembly Project::new shares: the two entries differ only in the tree and in the way named. A writer writes under the root the composition root gives it, which is not the tree's. An end that cannot be opened as asked (a revision that names no commit, Git outside a repository, a Git that does not know a form the reading uses, an index whose .gitattributes are not HEAD's, a directory that is not there or is no directory) is an OpenError of the request (exit 2). An OpenError of the run is no error of the request, and fails the run (exit 3), as an error met while reading does: no git to be found or started (NoGit), a Git that fails or runs past its time (Git), a directory of a side that cannot be looked at for another reason than nothing there, with the system's error (Unreadable), and adapters of the spaces that cannot be dispatched to (Dispatch). The way is named from what was asked, for an answer to say: git: <since> -> <until>, git: <since> -> the index, files: <before> -> <after>, with the project root for an after not asked. A local path the program knows is never written in it; the one exception is what a person wrote as an argument (a directory or a revision), written as it was typed, since it is the person's own text and nothing the program adds.
