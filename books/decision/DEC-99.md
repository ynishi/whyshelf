The domain knows no form of a name, so where the thing a name names lives in the files of the project is the adapter of its space's to say, through a fifth ask an adapter may answer (NamePlaces), declared by its type as the other four are, with the not-answering type CannotPlace, which places no name. The answer for each name is a Placement: Only, the thing is these files whole; Partly, these files hold part of it and the rest is outside the files of the project; or Unplaced, the adapter cannot say, with why. The files are paths of the project as written, the files the content of the name is read from at the side, read through the state by the rule the reading of the space follows links by: a name with no link on its way is its own path; one read through links inside the root lives in each link entry on its way, as written, and in the name they lead to, since its content depends on each; one read through a link that leaves the root, is broken or loops, or a thing the state cannot tell, is unplaced with the reason its reading gives. Every name asked has an answer; a text that is no name of the space is unplaced by the grammar alone, with no I/O, whatever is there; a name the adapter cannot place is unplaced and every other name is still answered, and an error is for what stops the whole ask (a side the run does not read). The ask reads at a side, as every ask that reads does (DEC-101). Where a name lives is never pinned and never hashed. The dispatch answers it for the use cases (ArtifactSource::places), and a name of a space no adapter names is unplaced, with why.

The space file places a name, whole, in the files its content is read from by that rule, with nothing opened: its own path when no link is on it, there or not, so a name with nothing there lives where it would be. The spaces rust-test and js-test place a test, whole, as the space file places the file its name writes before ::. The space rust-item places an item in part: the line Source of the heading of its page in the built docs, or of the element of a member (a field and a variant, declared in the body of their type, take their type's), names a page src/<crate>/<path>.html of the docs, and the file is <path> under the directory of the root file of the crate, a part up read as .., looked at in the tree of the side as the space file looks at one, and it must be a file there, while its docs are made by the build. Which directory holds a crate is read from the manifests of the side, never by running a program: the Cargo.toml at the root (its package) and those of the members of its workspace (a path, or a pattern of * and ? in its parts, what a pattern matches under a path of exclude taken out and a member written as a path kept), each read as the cargo settings are (through no link out of the root, at most MAX_SETTINGS_BYTES); when the root has no Cargo.toml, the Cargo.toml of each directory at the top of the tree (not one whose name starts with a dot) is read the same way with its members, the one rule of rust-item and rust-test (DEC-116); the dependencies of a package are not read as crates of the project. A crate is a library (the name and the path of [lib]; else, unless autolib = false, when the package has a file src/lib.rs, the name of the package with - as _ and src/lib.rs) or a binary: those cargo finds by the layout (src/main.rs by the name of the package, and each src/bin/<name>.rs and src/bin/<name>/main.rs by its name), unless autobins = false or the package is of the edition 2015 (the edition when none is written, or the workspace's when it is inherited), declares a [[bin]] and does not say autobins = true; and each [[bin]] in the place of a found one of its name, by its path, else the found one's, else src/main.rs by the name of the package, else src/bin/<name>.rs or src/bin/<name>/main.rs. A library and a binary of one name are the library. An item is unplaced when the docs cannot be read or do not have it, when its page cannot be read or links to no page of the source, when its crate is none of the manifests read (a dependency's, or one they do not reach), two packages have it, or something that might have it cannot be read (a manifest, a member written with ** or [, a member directory that is a symbolic link, a directory of a package's source that cannot be listed; a directory that is not there is only nothing there), when its path leads out of the project, or when the file is no file of the project or is read through a link that leaves the root; a source rustdoc keeps outside the directory of the crate's root file is named by its whole path, so it is no file of the project, and the reason does not repeat it. One conformance test holds every adapter to the ask as its type declares (DEC-84).
