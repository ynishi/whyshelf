The templates are data in the infra: a minimal declaration of one book with comments on how to extend it, and a sample of four books, finding, requirement, decision and verification, with their links, covers and the default artifact space file, and one document per book in one chain whose verification is a review that names no file. ShelfApp::init checks the declaration text with the parser and schema check every read uses, plans each document as new does on the documents planned before it, with its fixed key and a fresh identity, and refuses, naming every file in the way, when anything is at the declaration's path or a document's path, a directory or a link included, or a parent of one inside the root is there and is no directory, or when a file of a book already writes a key the template gives; only then it writes the declaration through DeclarationWrite, create-only, and then each document, removing a file it made when writing it fails, and only that file, so a failure part way leaves at worst a declaration with fewer documents, and the error names what was written and what failed. Nothing is approved. whyshelf init and init --sample answer the files written and the commands to run next; a refusal exits 2, as does a declaration template the schema refuses or a file that appears in between; a document template that cannot be read, or a port that fails, exits 3. Each command it gives next carries the --root it was given, and the approval it gives next names only the documents it made that none of them stands on, so it approves what it made and nothing else.
