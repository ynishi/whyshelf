title: "The state of a tree of names at one side of a change is read through one port generic in the name of the tree, and every reading of the project and every reading ask of a space take the side"
---
Every reader of a project reads the tree of names it is in through one port, StateRead and StateList, generic in the name of the tree: a path of the project, or a place in the built docs of rust-item. A reading is of one side of a change (Side): the side after is the project as it is, which every command reads, and the side before is the other end of a change, which only a run that compares two ends reads. The ports the use cases read (the declaration, the documents, the ledger, and the asks of a space that read: a reading, the current bytes, the names a selection takes) take the side. A use case reads the clock once and gives that time to each side it reads: load_at reads the declaration of a side and then its documents and its ledger, and load reads the side after so at a time read for it; a use case that answers a declaration that is not sound, or holds what it is asked against the declaration before the documents are read (check, status with a filter, cover, unlinked), reads the declaration (schema_of) and then the rest (load_with), at the same side and time. A run reads with one adapter of the tree, built and named by the composition root, so the two sides of a change are read by one implementation and what differs between them is the change. ReadWay is the way the run reads, which ShelfRead::way returns and an answer may name, and which the core does not read; a run of the files of the project names it "files: the project root", with no local path in it.

The ports are the core's, in its application layer, beside the other ports the use cases read through: load_at and the use cases hand the side to every port they read, so the side and what a reading of it answers are words of the application, and only the adapters that read a tree are the infrastructure's. The words of a tree in them (a file, a directory, a link, a kind that is none of them) are the kinds of place a tree has, whatever holds it.

What a name is at a side is one of five answers (AtSide): its bytes, within the bound the reader gives and one byte more, so that a reader tells a content past its bound by its length; nothing; a directory, with no bytes; the first part of it, from its start, that is a link, with the text the link holds and where the adapter resolves it to lead (a name of the tree, the top of the tree, out of it, to nothing when it is broken, or nowhere the adapter can resolve for another reason: a loop of links, a part on the way that is no directory, a place that may not be looked at); or that the adapter cannot tell, and why. Every name asked has an answer of its own, or an error of its own (NameAnswers): a name the system cannot read never stops the other names asked with it, and the error of the call is for what stops every name (a side the run does not read). A look (StateRead::look) answers the same of a name with a file told by its length, and opens nothing: what a reader asks to know that a name is a file within its bound before, or instead of, reading it, so that a listing of many files reads no more of a file than the byte that shows it opens and the one past it, and the search for moves and a walk of the built docs read none of it, to know what is there. A directory is listed with each entry's own kind, a link entry being a link whatever it leads to, and with the entries whose name is no name of the tree kept apart, each with where it is (Unnamed, Beyond: the directory it is under and its own parts as written), so that a reader that reads such an entry reads it there (read_beyond, list_beyond) and never by a name. The files of the tree are listed as the state lists the files of the project, and a listing that is not all of them says why (TreeFiles). A reading through a link that leaves the tree (read_outside, list_outside), a reading of an entry the tree cannot name (read_beyond, list_beyond), and the addresses a content can be read back by, are answered only by a run of one side: every other run cannot tell the first two and names no address, which an address may always be, so an address and a hash are of one reading.

The walk along the links of a name is one, and each reader gives it its own rule: the declaration, the documents and the ledger read through a link out of the root as the system reads a path, so a broken link is nothing there, and a link the adapter cannot resolve (a loop of links, a part on the way that is no directory, a place that may not be looked at) is read as the system resolves the path (read_outside, list_outside), which gives the system's own answer with its kind: a loop of links fails the reading, and a document's file through a part that is no directory is none now, as before. The spaces file, rust-test and js-test, and rust-item in the project, read through no link out of the root, nor through one that is broken or that the adapter cannot resolve. The declaration, a document's file and a record are read through every link by one reading, and the ledger and the directories of a range listed by one listing, whose answers each reader maps to its own errors. Each reader keeps its answers: nothing there, a directory, a file on the way, a loop of links and a file that cannot be read come to what they came to before. An entry of the ledger or of a range whose name is no path of the project is read where the system finds it, as before: a record of such a name is kept when it decodes, and fails the read (LedgerError::Name) when it does not, its name being one no answer can report; a directory of a range of such a name is walked, and a file the range takes in it fails the read (DocsError::Name). A kind of file that is none of a file, a directory or a link (a pipe) is not opened, and is told as a file that cannot be read is told: a failure of the whole reading for the declaration (BooksError::Untold), the documents (DocsError::Untold) and the ledger (LedgerError::Untold), and a name that cannot be told for a space. An entry of a range of documents that is of such a kind is passed over, as an entry that is a link is.

The modules that read are held to the port by the arch-lint rules readers-read-through-the-state (no std::fs, tokio::fs or Git written in them) and readers-ask-not-git (no Git reached through super): the reading of the declaration, the documents and the ledger, and of the spaces file, rust-test, js-test and rust-item (its space, its lookup, its catalog and its tree of the built docs). A reader's writer, its reading back by address, the search for moves of the space file, and the adapter of the built docs outside the project are modules of their own, outside the rules. The tests of rust-test, js-test and rust-item are in the module they test, and each line of them that sets up a tree on the file system carries an allow of its own; the rest of each module is held.
