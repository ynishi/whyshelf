One entry point of the domain, Shelf::form_entries, decides which entries of a front matter go in the form, and gives them as FormEntries, which nothing else can make: an entry that says nothing (Written::of) is left out when its book declares it an optional field, or a link to documents or to artifacts whose count admits none, as the build reads such an entry as not written; a required field, a link whose count does not admit none, the id, the key and an entry the book does not declare are kept, since leaving them out would change the problems. new writes FormEntries, and so does fmt: the use case reads each file through the port (its reading, its bytes, its first comment), asks the domain for FormEntries, has the adapter render them and read the text back, and writes only when that reading is the file's own reading with those entries, so no document, problem or hash changes; whether a file can be replaced is asked of the port only for a file not in the form that holds no comment. status --without FIELD, repeatable, admits a valid document of a book that declares the field and holds no value for it; a field asked with a value and with no value, and no value asked of a field every declaring book requires (of the books asked, when any are and one of them declares it), are request errors, as no document could pass; these two are the only refusals of that kind added, and --where FIELD= stays a request error. This repository's books declare their titles a line.
