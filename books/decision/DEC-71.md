One match over the kinds of cause says where each starts and what happened there; an origin keeps the events of its causes and the approvals that hold a cause there themselves. settle_all lists what can settle each origin: read the diff of an approval that holds the cause, declare the edit the same, look for moves and declare one, approve a pending upstream, approve by another name (--actor with a name to write in) an upstream whose approval awaits the approvals of other names (DEC-89), approve again with an expiry, each of these three by naming one document, in a run of one, and only when the frame that run meets (frame_approve, DEC-97, on the ledger before it) takes the approval, read once for the shelf, for the documents the settlements approve by name (settle::origins_asked), beside what --stale takes (order::Foreseen), and an origin is settled only with what was foreseen of it; an approval by name the frame refuses is not listed, and is told with the refusal (DEC-114); what only the person decides (the name, the time, a name that already approved) is not foreseen; and approve again what an edit made stale, the last only for an edit, an arrival or a changed link, and only when the shelf's own choice of what --stale takes holds one of the origin's approvals, a choice that leaves out, as the run does, what the frame of the approval refuses as the shelf and the ledger tell it before the run (DEC-97) and what stands on it. An upstream that is pending or awaiting, a link behind a move, a gone file, an invalid document and a cycle are not offered approving again, since it would settle nothing; nor is one that is superseded, since the frame refuses an approval on an upstream deprecated (DEC-5), which the run leaves out as refused. The command line writes each as a command, its names drawn from the clap definition and every command checked to parse, documents by their key in their book, with the run's root.
