---
Every adapter keeps a fourth promise, of its sources: it says on its page the sources its answers stand on, files of the side it is asked, and what it answers is told by their content and by nothing else. What is a source and what is derived is the role the adapter declares, not where a thing is. An adapter that reads something derived from its sources holds what it reads against them by content, as far as what it reads shows them, says on its page what it cannot hold, and answers that it cannot tell where what it reads is not of them: Untold::NotOfSources, which says what was read, how it is not of the sources (a file that differs, a copy of a file that is not there, no copy of the sources, or what could not be read) and what to do, made by ArtifactReading::not_of_sources. Each adapter writes what it stands on under the heading What it stands on, which the conformance test looks for; a hook declares whether its adapter reads its sources or something derived, and for the latter writes a tree where that is not of them, over which no name is there or absent and each is not of its sources.

The adapter of rust-item reads docs derived from the project's .rs files, its manifests and its cargo settings; CARGO_TARGET_DIR says only where the docs are. Before any page of the docs of a side is read, it holds them against the sources of that side once for the run: every page of the source the docs hold of a crate of the project is laid beside the file of the side it is of, compared byte for byte with the file as the compiler read it (a byte order mark at its start dropped, a CRLF as LF), the whole build at once, so that one page not as its file makes every name of those docs one that cannot be told, the first in the order of the paths saying why. A page under the build directory by its whole path is a source a build made and is not compared; a page under the root by its whole path is of the file under it; a page with a part up is read as before; any other page is of the first file of the side of its path under the directory of the crate's root file or a directory above it, up to the root. A crate of the project with no page of the source, a name two packages give their crates, a page that climbs out of the project, a manifest that cannot be read, and a bound passed hold no docs. The docs of a crate that is no crate of the project are not held, their names are not of the sources, and the search for moves does not walk them. A lookup of the docs is made only from the mark that they were held, so no reading of the docs (a reading, the current bytes, where names live, the search for moves) reads a page of docs that were not held. whyshelf builds nothing and runs no program: the recipe a check runs builds the docs first, CI runs the same recipe, a Git hook may help, and the manual says what cannot be held. An approval cannot stand on such a name, freshness does not change for it, check stays clean and stale --exit-code fails while an approval pins one (DEC-45).
