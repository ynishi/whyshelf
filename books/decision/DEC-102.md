The tree of a project in a directory is read by FileStates. A run of one side reads the root of the project as the side after and has no side before (FileStates::new, what every command builds, and a reading of the side before is an error of the port); a run of two reads a directory for each side (FileStates::between). A name is looked at part by part without following a link, as the space file looked at a path: the first part that is a link is answered with the text it holds and where it leads by its canonical path against the canonical directory of the side (a name there, the top of the tree, out of it, to nothing when the system finds nothing at what it names, or nowhere it can resolve when it cannot resolve it otherwise: a loop of links, a part on the way that is no directory, a place that may not be looked at), so a link into the root by an absolute path is inside it; a place inside whose path is no name of the tree is told as out of it, so a reader that reads through such a link reads it where the system finds it, and a reader that reads through every link reads one the adapter cannot resolve where the system finds it too, so that the system's own error comes back with its kind. At the end of the name, a file is read within the bound asked and one byte more, a directory has no bytes, and a kind that is none of a file, a directory or a link is not opened and cannot be told. A look walks the name the same way and tells a file by the length its metadata gives, opening nothing. A part on the way that is no directory is the system's own error, as a reading of the path is, and each reader tells it as it told that error; it is the error of that name alone, and the other names read with it are answered. The entries of a directory are its entries as written, each with its kind, its links not followed, and an entry whose name is no name of the tree is kept apart by its text, with the directory it is under and its part as written, so that a run of one side reads it, and lists what is under it, as the system resolves it; a run of two answers that it cannot be read alike at two sides (LEAVES). A reader names a place in what it says by FileStates::path_of (the directory of a side is FileStates::dir), and FileStates::with_timeout bounds each call of Git, for a test of the bound.

Only a run of one side reads through a link that leaves the tree, reading the name as the system resolves it, every link followed (a directory listed the same way, each entry by its own kind), and names the addresses of contents: the blob Git would store for each file of the root as it is (git hash-object), at the side after. A run of two answers that a link that leaves the project cannot be read alike at the two sides (LEAVES), and names no address. The files of the tree are those Git lists of the work tree of the side's directory (tracked, and not tracked and not ignored); outside a repository, or when Git cannot be run, they cannot be listed, and a listing cut at its bound, or one that leaves out files whose path is no path of the project, is not all of them. FileStates writes nothing and makes no directory, and its clones are one state: every reader of a run holds the same. A tree of a commit or of the index is read by GitStates (DEC-103), by the same rules of what a run of two answers. Whether a run reads what the system resolves (a link out of the tree, a place that is no name of it, docs outside) is said in one place, by the run's state, with one reason (LEAVES).
